How to open this

Downloading this page on its own, or viewing it in a preview pane, leaves it with nothing to link to. The status pill on each card tells you which case you are in.

What "synced" means here, and what was verified

One model, five surfaces All five applications embed the same shared core and read and write the same browser-local state under cx_state_v1, with a change bus on cx_bus_v1 and a companyx_v1 broadcast channel. Submit an application in the Farmer App and it appears in the Officer Workbench queue, the Command Centre portfolio and the Ops console — in the same browser session, without a reload. Use Open all five above and keep the tabs open to see it happen. This was tested end to end, not assumed: a record written in one app was confirmed present in memory and in storage in all four others.

One deliberate difference between the builds The Ops console carries internal input-margin data — target and achieved margin per crop, the margin bridge, and the P&L — that the farmer, buyer and Landbank builds do not. That omission is intentional and should stay: the shared state schema is identical, so sync is unaffected, but Kita's input economics do not belong in a surface a buyer or the bank can open.
What is still not true There are no signed buyer offtake agreements. Every buyer, volume and price in these applications is illustrative. The per-crop matching fee schedule is a recommendation and no buyer has agreed to any rate in it. The tripartite structure names Kita as a service party, and whether the buyer's payment undertaking is enforceable by Landbank — who is not a party to it — has not been confirmed by counsel. Nothing here should be presented as evidence of contracted demand.
